# 租租侠边界测试用例

对应《软件开发计划书》8.2 节测试重点，以及设计文档第 10 节。

这 6 个用例是**验收演示的加分点** —— 主流程谁都能跑通，边界条件才见功力。
建议演示时专门留 2 分钟走一遍。

---

## 前置准备

```bash
# 1. 建库并导入数据
mysql -u root -p < docs/db/schema.sql
mysql -u root -p zuzuxia < docs/db/data.sql

# 2. 启动前后端
scripts/start-all.bat
```

- 出租人：`wujiahao / 123456`（伍嘉豪，发布物品 1、2、7、10、16、21）
- 租用人：`hejinquan / 123456`（何金泉）
- 管理员：`admin / admin123`

## TC-01 在不可租时段提交申请

| 项 | 内容 |
|---|---|
| **目标** | 验证系统会拒绝超出出租人设定窗口的租借 |
| **前置** | 物品 1「佳能 EOS R6」的可租区间为 2026-09-01 ~ 2026-12-31 |
| **步骤** | 1. 以 `hejinquan` 登录<br>2. 打开物品 1 详情<br>3. 直接构造请求：租期选 2027-01-05 ~ 2027-01-07 |
| **预期** | 返回 `1004 该时段已被租用`（或专门的"不在可租时段"提示），订单不创建 |
| **注意** | 前端日期选择器应直接禁用窗口外的日期；本用例主要验证**后端不会因为前端绕过而放行** |

---

## TC-02 对同一物品同一时段重复申请

| 项 | 内容 |
|---|---|
| **目标** | 验证时段冲突检测 |
| **前置** | 物品 7「牧高笛三人帐篷」已有一单 RETURNING，租期 2026-09-10 ~ 2026-09-14 |
| **步骤** | 1. 以 `hejinquan` 登录<br>2. 对物品 7 提交申请，租期选 2026-09-12 ~ 2026-09-15（与已有订单重叠） |
| **预期** | 返回 `1004 该时段已被租用`，订单不创建 |
| **补充** | 同时验证**部分重叠**也算冲突：2026-09-14 ~ 2026-09-16 的首日与已有订单末日重合，必须拦截 |

---

## TC-03 租借自己发布的物品

| 项 | 内容 |
|---|---|
| **目标** | 验证自租拦截 |
| **前置** | 物品 1 的 `owner_id` 为 `wujiahao`(2) |
| **步骤** | 1. 以 `wujiahao` 登录<br>2. 打开自己发布的物品 1 详情 |
| **预期** | 返回 `1006 请勿租借自己的物品`；前端详情页对本人应直接隐藏"申请租借"按钮 |

---

## TC-04 余额不足以支付租金 + 押金

| 项 | 内容 |
|---|---|
| **目标** | 验证下单前的余额校验 |
| **前置** | 物品 2「索尼 A7M4」租金 95/天、押金 2000。新注册用户余额为 0 |
| **步骤** | 1. 注册一个新用户（余额 0）<br>2. 对物品 2 提交 3 天申请（需 285 + 2000 = 2285） |
| **预期** | 返回 `1003 余额不足`，并提示还差多少；订单不创建 |
| **补充** | 校验应发生在**下单时**而非同意时 —— 否则出租人同意后才发现租用人付不起，体验很差 |

---

## TC-05 两人同时对同一单点"同意"

| 项 | 内容 |
|---|---|
| **目标** | 验证并发下的时段独占 |
| **前置** | 物品 16「iPad Pro」在 2026-09-20 ~ 2026-09-22 无进行中订单 |
| **步骤** | 1. 用 A、B 两个账号（非物品所有者）同时对该时段提交申请<br>2. 出租人先同意 A 的申请<br>3. 出租人再同意 B 的申请 |
| **预期** | 第 2 步成功，订单进入 `RESERVED`，押金冻结、租金扣除；<br>第 3 步返回 `1004 该时段已被租用` |
| **关键** | 同意时必须**二次校验**时段占用，不能只依赖下单时的校验 |

---

## TC-06 对同一订单重复评价

| 项 | 内容 |
|---|---|
| **目标** | 验证一单一人一评 |
| **前置** | 订单 1 已完成（FINISHED），何金泉已作为 RENTER 评价过 |
| **步骤** | 1. 以 `hejinquan` 登录<br>2. 对订单 1 再次提交评价 |
| **预期** | 返回 `1013 你已经评价过该订单` |
| **兜底** | 即使业务层漏判，数据库唯一索引 `review.uk_order_reviewer` 也会拦下，表现为 `409 操作冲突` |

---

## 补充建议：另外两个值得加测的点

| 编号 | 场景 | 为什么值得测 |
|---|---|---|
| TC-07 | 出租人在未到租期时确认归还 | 应拦截或给出明确提示，防止状态机被跳跃推进 |
| TC-08 | 订单未完成时提交评价 | 应返回 `1007 订单未完成，无法评价` |
